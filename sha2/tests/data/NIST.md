# NIST SHA-224/SHA-256 test vectors

These fixtures contain a subset of the **byte-oriented SHA-224 and SHA-256**
response sets from NIST's
[secure hashing test vectors](https://csrc.nist.gov/projects/cryptographic-algorithm-validation-program/secure-hashing).
They do not include the bit-oriented tests or other SHA variants.

Source archive:
[shabytetestvectors.zip](https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Algorithm-Validation-Program/documents/shs/shabytetestvectors.zip)

Archive SHA-256:
`929ef80b7b3418aca026643f6f248815913b60e01741a44bba9e118067f4c9b8`

For each algorithm:

- `SHA{224,256}ShortMsg.rsp`: CAVS 11.0, March 15, 2011; 65 messages,
  covering every byte length from 0 through 64.
- `SHA{224,256}LongMsg.rsp`: CAVS 11.0, March 15, 2011; only the longest
  message (6,400 bytes, or 100 blocks) of the 64 supplied messages is retained
  to limit the published crate size.
- `SHA{224,256}Monte.rsp`: CAVS 11.1, May 11, 2011; one seed and 100 expected
  outer-loop results, each after 1,000 hashes (200,000 hashes across both algorithms).

The `*_short.blb` and `*_long.blb` files use the existing blobby 0.4
input/output-pair format. The Monte Carlo files contain the initial seed followed
by the 100 expected digests. No expected result is generated by this crate.
The complete ShortMsg and Monte Carlo sets are retained. The importer checks
the archive hash, record counts, byte lengths, and all expected results
(including the omitted LongMsg cases) using Python's hashlib.
NIST's `Len = 0, Msg = 00` becomes an empty input.

To reproduce the six fixtures, download the archive above and run from the
repository root:

```sh
python3 sha2/tests/data/import_nist.py /path/to/shabytetestvectors.zip
```

The tests require no network access. Short/long messages use the existing
`fixed_reset_test` helper, including whole-message, reset, and chunked updates.
To run all six tests:

```sh
cargo test -p sha2 --release --test nist -- --test-threads=1
```

For runtime measurements, build once with `--no-run`, then time the resulting
test executable with `--test-threads=1`. This excludes compilation and
makes the six tests run sequentially.
